# DNA Client Folder Structure

This document outlines the folder structure and setup of the `dna-client` project to serve as a blueprint for implementing a similar structure in another project. The project is built using React, Vite, TypeScript, and Tailwind CSS.

## Root Directory

The root directory contains configuration files, dependency management, and top-level folders.

- **`.github/`**: Contains GitHub Actions workflows for CI/CD pipelines.
- **`dist/`**: The output directory for the production build generated by Vite.
- **`docs/`**: Documentation files (e.g., API docs, design system).
- **`public/`**: Static assets that are served directly at the root path (e.g., favicon, robots.txt, manifest).
- **`src/`**: The main source code directory where the application logic resides.
- **`package.json` & `package-lock.json`**: Defines NPM dependencies, scripts, and project metadata.
- **`vite.config.ts`**: Configuration for Vite, the build tool and development server.
- **`tailwind.config.js` & `postcss.config.js`**: Configuration files for Tailwind CSS and PostCSS (styling).
- **`tsconfig.json` & `tsconfig.node.json`**: Configuration rules for the TypeScript compiler.
- **`Dockerfile`, `nginx.conf`, `nixpacks.toml`, `vercel.json`**: Configuration files for Docker containerization, NGINX routing, and deployment (Vercel/Nixpacks).
- **`.eslintrc.cjs` & `.prettierrc`**: Configuration files for ESLint (code linting) and Prettier (code formatting).

## `src/` Directory Structure

The `src/` directory is highly organized into specific modules and responsibilities. 

```text
src/
├── @types/       # Custom global TypeScript type definitions
├── api/          # API service functions for backend communication
├── assets/       # Static assets imported into components (images, icons)
├── auth/         # Authentication logic and higher-order components
├── components/   # Reusable UI components (buttons, modals, tables, etc.)
├── configs/      # Application-wide configuration and environment variables
├── constants/    # Constant values used throughout the app
├── context/      # React Context providers for global state
├── helpers/      # Small helper functions for specific tasks
├── hooks/        # Custom React hooks (e.g., data fetching, UI state)
├── layout/       # Layout components (Sidebar, Navbar, wrappers)
├── lib/          # Third-party library initializations/wrappers (e.g., Axios instance)
├── navigation/   # Navigation and routing logic/helpers
├── pages/        # Main application views/pages (e.g., login, dashboard)
├── providers/    # Global context providers wrapping the app (Theme, Auth, QueryProvider)
├── store/        # Global state management (e.g., Redux store, Zustand)
├── types/        # Global TypeScript interfaces and type declarations
├── utils/        # General utility functions (date formatting, validation)
├── App.tsx       # Root React component
├── main.tsx      # Application entry point (renders App to the DOM)
├── router.tsx    # React Router configuration
└── index.css     # Global CSS styles (includes Tailwind directives)
```

### Detailed Breakdown of Key `src/` Folders

#### `api/`
Contains files dedicated to making HTTP requests to your backend endpoints. It is separated by feature/entity (e.g., `auth.api.ts`, `user.api.ts`, `course.api.ts`). This abstracts the fetching logic away from the UI components.

#### `components/`
This folder is for reusable, generic UI elements. 
- **Subfolders** exist for complex components or groups of related components (e.g., `Button/`, `Table/`, `modals/`, `ui/`, `VideoPlayer/`).
- **Standalone Files** for simpler components (e.g., `Alert.tsx`, `Select.tsx`, `Tooltip.tsx`).
By keeping these components isolated, they can easily be reused across different pages.

#### `pages/`
Contains the actual views or screens of the application. These are usually tied to specific routes.
- Organized by feature or module (e.g., `dashboard/`, `profile/`, `signup/`).
- Top-level files for standalone pages (e.g., `login.tsx`).

#### `hooks/`
Contains custom React hooks to encapsulate reusable stateful logic or side effects (e.g., `useAuth`, `useFetchData`, `useWindowSize`).

#### `layout/`
Contains components that define the page structure, such as headers, sidebars, footers, and main content wrappers. Pages are typically injected as children into these layouts.

#### `store/` & `context/`
These folders manage state that needs to be accessed globally across many components.
- `context/` is generally used for simpler state (like theme or simple auth state) using React Context API.
- `store/` is used for more complex, scalable global state management libraries (like Redux Toolkit or Zustand).

#### `utils/` & `helpers/`
These folders contain pure JavaScript/TypeScript functions that don't depend on React. They are used for formatting dates, string manipulation, data validation, or mathematical calculations.
